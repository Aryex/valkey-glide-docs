The address resolver feature allows you to provide a custom callback that translates server addresses during connection establishment and cluster topology refreshes. This is useful for custom DNS resolution, proxy-based address translation, or dynamic endpoint resolution in cloud environments.

## Configuration

The `addressResolver` option accepts a synchronous callback that receives a host and port, and returns a translated `[host, port]` tuple.

  <TabItem label="Go">
    ```go
    import (
        "github.com/valkey-io/valkey-glide/go/v2"
        "github.com/valkey-io/valkey-glide/go/v2/config"
    )

    // Define the address resolver function
    resolver := func(host string, port int) (string, int) {
        // Translate internal hostnames to actual endpoints
        if host == "internal-service.local" {
            return "10.0.1.100", port
        }
        return host, port
    }

    // Standalone client with address resolution
    clientConfig := config.NewClientConfiguration().
        WithAddress(&config.NodeAddress{Host: "internal-service.local", Port: 6379}).
        WithAddressResolver(resolver)
    client, err := glide.NewClient(clientConfig)

    // Cluster client — resolver is also invoked during topology refreshes
    clusterConfig := config.NewClusterClientConfiguration().
        WithAddress(&config.NodeAddress{Host: "cluster.proxy.local", Port: 6380}).
        WithAddressResolver(func(host string, port int) (string, int) {
            // Map cluster node addresses through a proxy
            return "proxy.internal", port + 1000
        })
    clusterClient, err := glide.NewClusterClient(clusterConfig)
    ```

    import { GlideClient, GlideClusterClient } from "@valkey/valkey-glide";

    // Standalone client with address resolution
    const client = await GlideClient.createClient({
        addresses: [{ host: "internal-service.local", port: 6379 }],
        addressResolver: (host: string, port: number): [string, number] => {
            // Translate internal hostnames to actual endpoints
            if (host === "internal-service.local") {

            return [host, port];
        },
    });

        },
    });

## How It Works

1. **Registration** — The resolver callback is registered in a global registry before the connection is established.
2. **Invocation** — The resolver is called for each configured address during initial connection and during cluster topology refreshes (for cluster clients).
3. **Cleanup** — The resolver is automatically removed from the global registry when the client is closed or if the connection fails.

## Fallback Behavior

If the resolver throws an exception or returns an invalid value, the original address is used as a fallback. This ensures that a faulty resolver does not prevent the client from connecting.

## Limitations

- **Node.js**: The resolver callback must be **synchronous** — async resolvers are not supported. The resolver runs on the Node.js main thread; long-running resolution logic could block the event loop.
- **Go**: The resolver uses a global registry pattern — if multiple clients are created with different resolvers, each client keeps its own resolver, but the resolver must be safe for concurrent use from multiple goroutines. If the resolver panics or returns an empty host or port 0, the original address is used as fallback.
